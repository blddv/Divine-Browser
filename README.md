# Divine Browser / DivineWeb v2.0

**DivineWeb v2.0** — нативный графический 2D веб-браузер для Linux, написанный преимущественно на компилируемом языке **HolyC** (`holyc-lang`), с встроенным движком QuickJS на C с прямой отрисовкой через **X11 + Cairo**, декодированием растровой и векторной графики через **GdkPixbuf / librsvg**, шифрованием **OpenSSL TLS** и встроенной глобальной **P2P-сетью «HOLYNET» (Холинет)**.

> Экспериментальный проект, не замена Firefox/Tor Browser. Нет полноценной
> песочницы и совместимости с современными веб-стандартами. Обычный HTTP(S)
> **не идёт через Tor**. Не используйте браузер для паролей, платежей и задач,
> требующих надёжной анонимности.

## Быстрый старт

Исходники распакованы в корень репозитория. Исходный
`DivineWeb-Holynet-Tor.tar.gz` сохранён; повторно распаковывать его не нужно
(распаковка поверх рабочей копии перезапишет файлы из архива).

Для комплектных бинарников нужны **Linux x86-64, glibc ≥ 2.38** и системные
библиотеки из раздела сборки. Из корня проекта:

```bash
./holy-browser --help
./holy-browser ./demo.html

# Локальная страница в PNG без X-сервера и обращения к Интернету:
./holy-browser --screenshot demo.png ./demo.html
```

Для окна нужен X11 либо XWayland с корректным `$DISPLAY`. Режим `--screenshot`
не требует X-сервера, но графические библиотеки всё равно нужны. Не запускайте
браузер от root. Для Холинета сохраняйте `vendor/tor/tor` рядом с браузером
в исходной структуре каталогов.

## Безопасность Холинета: экспериментальный режим

**Важно:** в действующих протоколах HOLY/1.0 и WORLD_MESH публикации и домены не подписаны. Любой участник публичного MQTT-брокера может подделать анонс, содержимое, владельца и счётчики, в том числе выдать себя за уже известный узел. Совпадение текстового ID или запомненного владельца — не доказательство подлинности; файл `holynet_node_*.key` содержит только короткий идентификатор, а не криптографический ключ. Имена `holy://` не связаны с владением обычными доменами. Для настоящей защиты от подмены потребуются подписи, устойчивые публичные ключи и модель доверия для распределения имён. **Не вводите в Холинете пароли, платёжные и личные данные.**

Применённые базовые меры:

- Для сайтов Холинета JavaScript по умолчанию выключен. `Ctrl+J` явно включает его на текущей вкладке и перезагружает страницу; повторное нажатие выключает. Автоматические переходы скриптов в этом режиме заблокированы. Это ограничение безопасности, а не полноценная песочница.
- В строке состояния постоянно показано предупреждение `НЕПРОВЕРЕННЫЙ P2P` и состояние JS. Если домен не найден, больше не утверждается, что он свободен: каталог может быть неполным.
- Встроенные CSS-файлы не обращаются к Интернету, ссылки со страницы в `file:`, `http:` и `https:` при клике блокируются; прямой адрес можно ввести вручную. Изображения веб- и Holy-страниц не читают `file://` с диска. Для изображений Холинета допустимы простые встроенные изображения; SVG с внешними ссылками и некоторыми XML-конструкциями отклоняется. Фильтрация SVG консервативна и может отклонить корректные картинки; не заменяет изоляцию декодера.
- Проверяются размер, поля и согласованность сетевых пакетов и чанков; чужие объявления не перезаписывают локальные публикации. Смена текстового ID в текущем каталоге отклоняется, но подделку самого ID это **не предотвращает**. Прямые соединения HOLY/1.0, автоматический PEX и ручные пиры отключены: в сети используется только Tor и TLS-ретранслятор.
- TLS глобального ретранслятора и обычного HTTPS проверяет сертификат по системным CA и имени/IP сервера; откат на открытый MQTT/TCP отключён. Это защищает соединение до брокера, **не авторство сайтов**. Прямой HOLY/1.0 в этой сборке отключён.
- Отключена публичная рассылка каждого просмотра (`rpc/hit`), но приватности или анонимности это не гарантирует: брокер и участники могут наблюдать сообщения, публичный идентификатор и опубликованные данные. Не публикуйте секреты. Временные файлы изображений и gzip создаются через `mkstemp` с непредсказуемыми именами и правами 0600.

### Встроенный Tor для Холинета

В дистрибутив уже включён Tor 0.4.9.17 (`vendor/tor/tor`); отдельно Tor скачивать и устанавливать не нужно. При включении Холинета браузер запускает отдельный дочерний Tor, обращается к нему через приватный Unix SOCKS5-сокет, проверяет PID процесса на сокете и передаёт **имя** брокера для разрешения внутри Tor. Затем устанавливается TLS с проверкой сертификата и имени. Все соединения Холинета идут этим путём; прямой сетевой fallback не предусмотрен. При отсутствии или отказе Tor Холинет останется без сети; после аварии Tor перезапустите браузер. Первый запуск и загрузка каталога могут занять десятки секунд; обновите страницу после подключения. В headless-режиме ожидание — до 45 секунд.

Tor скрывает исходный IP от обычных пиров и MQTT-брокера при исправной работе, но **провайдер и оператор входного узла видят ваш IP и соединение с Tor**. Брокер видит IP выходного узла Tor, публичный ID, публикации и сообщения. Постоянный ID и содержимое позволяют связывать активность; старые клиенты могли сохранить прежний IP. Не гарантируется защита от анализа трафика, компрометации системы, атак локального пользователя с теми же правами, подмены сайта или слежки. Схемы распределённого доверия, подписи содержимого, полноценного sandbox и независимого аудита нет. Не используйте эту сборку для ситуаций, требующих гарантированной анонимности. Tor использует временный каталог в `/tmp`; аварийное завершение может оставить его на диске, а при каждом запуске выбираются новые guard-узлы (это может ухудшать защиту от долгосрочного анализа). Tor сам может быть заблокирован сетью; мосты обхода здесь не настроены.

**Обычные `http://` и `https://` страницы и их ресурсы через Tor не маршрутизируются**, могут напрямую раскрыть IP и DNS и не являются анонимными. Открывайте только `holy://`, если цель — транспорт Холинета через Tor. Нет автоматического переключения на прямое соединение при отказе Tor, TLS или брокера. Старые узлы с одним HOLY/1.0 недоступны; `--peer` отключён, `--p2p-port` выбирает локальный профиль. Запускайте из записываемой директории; там сохраняются публичный ID, блокировка профиля и ваши сайты.

Сборка предназначена для **Linux x86-64 с glibc 2.38 или новее**. Включённый Tor динамически использует системные libevent 2.1, OpenSSL 3, zlib, liblzma и zstd; самому браузеру также нужны его обычные графические и TLS-библиотеки. Бинарник Tor собран здесь из официального архива; копия исходников, подписанная контрольная сумма и ключ находятся в `tor-vendor/`, лицензия — в `vendor/tor/LICENSE`. Подпись суммы проверена ключом David Goulet с отпечатком `B74417EDDF22AC9F9E90F49142E86A2A11F48D36`, опубликованным на странице Tor Project. Сетевые обновления Tor автоматически не устанавливаются: обновляйте всю сборку, чтобы получать исправления безопасности.

## QuickJS и упрощённый Legacy CSS

Встроен QuickJS (исходники и лицензия — в `quickjs/`). Страница получает отдельный контекст; поддерживаются базовые изменения DOM, inline-скрипты, ограниченная загрузка внешних скриптов, обработчики кликов, таймеры, `fetch`/`XMLHttpRequest` и переходы через `location`. Клавиша **Ctrl+J** включает или выключает JavaScript для текущей вкладки и перезагружает её; в Холинете JavaScript выключен по умолчанию. Неизменённые локальные страницы без скриптов разбираются прежним HTML-парсером.

Сетевые запросы JS разрешены только к тому же HTTP(S)-origin, что и исходная страница; сетевые редиректы ресурсов не выполняются. На страницу допускается до 8 внешних скриптов и 16 JS-запросов; ответ ограничен размером до 768 КиБ в сетевом клиенте. Контекст QuickJS ограничен 64 МиБ и имеет тайм-аут выполнения. Файловые URL через JS-fetch не доступны. CSS-файлы из Интернета в режиме `holy://` не загружаются. Эти ограничения — упрощение, а **не полноценная браузерная песочница**: не используйте этот экспериментальный браузер для недоверенных сайтов, секретов или банковских операций.

CSS — намеренно небольшой поднабор примерно CSS 2.1, а не полная реализация стандарта. Работают стили из `<style>`, до четырёх внешних таблиц HTTP(S) и атрибутов `style`, простые селекторы тега, класса, идентификатора и предка, базовые цвета и оформление текста, цвет фона `body`, `display: none` и `visibility: hidden`. Для неподдерживаемого градиента берётся первый простой HEX-цвет как запасной фон. `!important`, точная блочная модель (фон отдельных блоков, рамки, поля и отступы), выравнивание, сложные селекторы и современная CSS-вёрстка не реализованы; часть значений может быть разобрана, но не применена в рендерере.

DOM/BOM, сетевой стек и API браузера тоже существенно неполны: CORS, cookies, JS-модули, события и формы не эквивалентны обычному браузеру, а JS-запросы выполняются синхронно и могут задержать интерфейс. Защиты сайтов, требующих современные Web API, проверки ботов или полноценный браузер, могут по-прежнему не работать. JS-таймеры обрабатываются только у активной вкладки.

Проверка сборки и регрессий: `make clean all test` (нужны C-компилятор, `ar`, `python3`, HolyC `hcc` и графические/сетевые библиотеки из раздела сборки). Тесты проверяют DOM/клики/таймеры/редиректы/watchdog, ограничения origin, разбор CSS и HTTP-загрузку, TLS и защиту P2P-пакетов. Linux-тесты проверяют отсутствие TCP/UDP в процессе Холинета, отключение при отказе Tor, SOCKS и удалённое разрешение имени; GUI-клики отдельно не автоматизированы.

## Что нового в DivineWeb v2.0

1. **Многовкладочный интерфейс (Multi-Tab Browsing)**:
   - До **8 независимых вкладок** одновременно — в одних вкладках может быть открыт обычный Интернет (`https://`), а в других — P2P-сайты Холинета (`holy://`), у каждой вкладки своя история `Назад`/`Вперёд`, свой скролл и масштаб.
   - Индикатор сети прямо на ярлыке вкладки (синий — Интернет, зелёный — Холинет).
   - Управление: кнопка `[+]` и `[x]` на панели вкладок, `Ctrl+T` (новая вкладка), `Ctrl+W` (закрыть вкладку), `Ctrl+Tab` (переключить вкладку), **средняя кнопка мыши** или **`Ctrl + клик`** по любой ссылке (открыть в новой вкладке).
2. **Панель Избранного / Закладок (`bookmarks.conf`)**:
   - Постоянная панель быстрого доступа под адресной строкой.
   - Кнопка **`☆ / ★`** рядом с адресной строкой (или горячая клавиша `Ctrl+D`) мгновенно добавляет или удаляет текущий сайт из закладок и сохраняет список на диск в `bookmarks.conf`.
3. **Настоящий рендеринг изображений `<img>` (`image_loader.HC`)**:
   - Поддержка **PNG, JPEG, SVG, GIF, WebP, BMP** с корректным альфа-премультиплицированием в поверхность `CAIRO_FORMAT_ARGB32`.
   - Загрузка картинок по `https://`, `http://`, `file://`, а также встроенных векторных иллюстраций `data:image/svg+xml,...`.
   - В режиме **Холинета** внешние HTTP/HTTPS-запросы к картинкам строго заблокированы (разрешены только проверяемые встроенные `data:image/...`), чтобы сохранять полную изоляцию суверенной P2P-сети.
4. **Настоящая 2D-вёрстка HTML-таблиц `<table>` (`LayoutHtmlTable`)**:
   - Автоматический расчёт ширины колонок (`<tr>`, `<th>`, `<td>`), многострочный перенос слов внутри ячеек, шапки таблиц, зебра-чередование строк, сетка границ и кликабельные ссылки внутри ячеек (отлично рендерит таблицы релизов `kernel.org`, инфобоксы Wikipedia и таблицы мониторинга P2P).
5. **Поиск по тексту открытой страницы (`Ctrl+F` / кнопка `Стр?`)**:
   - Всплывающая панель в правом нижнем углу (`На странице: [...] 1/N [▲] [▼] [x]`).
   - Регистронезависимый поиск на **русском (UTF-8 кириллица + ё/е)** и **английском**, подсветка всех совпадений жёлтым маркером, текущего совпадения — оранжевым, с автоматической прокруткой к найденному месту.
6. **Масштабирование страницы (Zoom `70%` — `180%`)**:
   - Кнопки `[-]` и `[+]` на верхней панели, горячие клавиши `Ctrl +`, `Ctrl -`, `Ctrl 0` и `Ctrl + колёсико мыши` с мгновенным пересчётом вёрстки.
7. **Расширенная типографика и цвета HTML**:
   - Поддержка `<mark>` (жёлтое выделение), `<s>` / `<del>` / `<strike>` (зачёркивание), `<u>` / `<ins>`, `<span style="color:#RRGGBB">` / `<font color="#...">` и расширенных HTML-сущностей (`&rarr;`, `&larr;`, `&bull;`, `&laquo;`, `&raquo;`, `&mdash;`, числовых `&#...;`).
8. **Улучшения глобальной P2P-сети «HOLYNET» (Холинет)**:
   - **Сохранение ваших сайтов на диск (`holynet_sites/`)**: все домены и сайты, опубликованные вами в Конструкторе, автоматически сохраняются на диск и поднимаются при следующем запуске браузера.
   - **Глобальный обмен через Tor + TLS-реле**: прямые пиры и слушающий TCP-порт отключены; провайдер видит соединение с Tor.
   - Векторная SVG-эмблема, прямая загрузка готовых `.html` файлов (`--publish-html`, омнибокс `загрузить <домен> <файл.html>` или кнопка в Конструкторе) и наглядные 2D-таблицы узлов и доменов на `holy://home` и `holy://monitor`.
9. **Тема «Одобрение Дэвиса» (`THEME_DAVIS`, `--davis`, `--davis-640`)**:
   - Строгое соблюдение канонов оформления Терри А. Дэвиса и **TempleOS** на **всех сайтах и во всём интерфейсе**:
     1. **Ровно 16 аппаратных цветов стандартной палитры VGA** (`0x00`/`0x55`/`0xAA`/`0xFF`: `BLACK`, `BLUE`, `GREEN`, `CYAN`, `RED`, `PURPLE`, `BROWN`, `LTGRAY`, `DKGRAY`, `LTBLUE`, `LTGREEN`, `LTCYAN`, `LTRED`, `LTPURPLE`, `YELLOW`, `WHITE`) + финальный квантователь кадра `EnforceDavis16Surface` (гарантирует **0 пикселей** вне 16-цветной палитры VGA).
     2. **16-цветный упорядоченный дизеринг Байера 4×4 (`GetOrBuildDavis16ImageSurface`)** для всех растровых и SVG-изображений на любых сайтах с `CAIRO_FILTER_NEAREST` и жёсткой 1-битной прозрачностью без полупрозрачного мыла.
     3. **Полное отключение субпиксельного сглаживания (`CAIRO_ANTIALIAS_NONE`)** как для векторной графики, так и для глифов шрифта, и принудительный **единый моноширинный шрифт** на всех сайтах и в UI.
     4. **Стилистика TempleOS DolDoc**: синяя шапка `BLUE` (`#0000AA`), бирюзовая полоса `CYAN` (`#00AAAA`) с живой шкалой 16 цветов `16c:`, двойная рамка окна документа, красные подчёркнутые ссылки в духе `$LK,"...",A="..."$` и **Оракул Дэвиса (`F7`)** прямо в строке состояния.
     5. **Канонический видеорежим `640×480` (`--davis-640`)** с адаптивной компактной раскладкой верхней панели, вкладок и закладок.

## Структура проекта на HolyC

| Файл | Назначение |
|---|---|
| `quickjs/`, `js_engine.HC` | Встроенный QuickJS, C-мост и ограниченная среда DOM/BOM |
| `css_legacy.HC` | Компактный поднабор CSS 2.1, без современной блочной вёрстки |
| `bindings.HH` | HolyC `extern "c"` привязки к Linux libc, POSIX sockets, `pthread`, `libX11`, `libcairo`, `libgdk_pixbuf-2.0` и `OpenSSL` |
| `url_http.HC` | UTF-8 безопасные строковые утилиты, парсер URL, резолвер ссылок и сетевой клиент HTTP/1.1 + OpenSSL TLS с редиректами |
| `image_loader.HC` | Декодер растровых и векторных изображений (`PNG`, `JPEG`, `SVG`, `GIF`, `WebP`, `data:image/svg+xml`) в Cairo `ARGB32` |
| `html_dom.HC` | Токенизатор и построитель DOM-потока (`<h1>`–`<h4>`, `<p>`, `<ul>/<ol>/<li>`, `<table>/<tr>/<th>/<td>`, `<img>`, `<mark>`, `<s>`, `<a>`, `<pre>`, `<code>`, HEX-цвета) |
| `layout_render.HC` | 2D-движок вёрстки (с масштабированием Zoom, таблицами и картинками), рендерер вкладок, закладок, `Ctrl+F` и 3 тем (`TempleOS`, `Modern`, `Холинет`) |
| `holynet_p2p.HC` | Реестр неподписанных доменов Холинета, хранение сайтов, мониторинг и запуск TLS-реле; прямой HOLY/1.0 выключен |
| `holynet_search.HC` | Полнотекстовый поисковый движок по P2P-сети (русская кириллица UTF-8 + латиница, ранжирование по доменам, заголовкам и тексту) |
| `holynet_builder.HC` | Интерактивный графический 2D-конструктор сайтов на Cairo |
| `browser.HC` | Главный модуль окна X11, менеджер вкладок, закладок `bookmarks.conf`, омнибокса, горячих клавиш и CLI |

## Сборка и запуск

### Зависимости

- Linux, `make`, C-компилятор и `ar` (например, GCC/binutils).
- Компилятор HolyC **`hcc` из holyc-lang**, совместимый с исходниками и опцией
  `-clibs`. Это не одноимённые компиляторы других языков. Сам toolchain в архив
  не входит; его установку и совместимость нужно обеспечить отдельно.
- X11, Cairo, GdkPixbuf/GObject, OpenSSL и zlib; для SVG нужен загрузчик librsvg
  для GdkPixbuf. Доступность WebP/GIF и других форматов зависит от установленных
  загрузчиков GdkPixbuf.
- Для комплектного Tor: libevent 2.1, OpenSSL 3, zlib, liblzma, libzstd и
  glibc ≥ 2.38. Пересборка одного браузера это требование Tor не устраняет.
- Для тестов: Python 3 и утилита `openssl`.

Пример пакетов для **Ubuntu 24.04** (HolyC устанавливается отдельно):

```bash
sudo apt update
sudo apt install build-essential python3 openssl ca-certificates \
  libx11-dev libcairo2-dev libgdk-pixbuf-2.0-dev libglib2.0-dev \
  libssl-dev zlib1g-dev librsvg2-common libevent-2.1-7t64 \
  liblzma5 libzstd1 fonts-dejavu-core
```

В других дистрибутивах названия пакетов могут отличаться. Например, glibc 2.36
из Debian 12 недостаточно для комплектных бинарников: используйте более новую
систему либо пересоберите браузер и Tor под свою платформу. Не заменяйте
системную glibc вручную ради запуска.

### Сборка из исходников

`Makefile` ищет `/home/user/hcc-toolchain/bin/hcc`, затем `hcc` в `PATH`.
Путь можно задать явно. QuickJS собирается из включённых исходников,
Tor этой командой **не пересобирается**.

```bash
# -B принудительно пересобирает и комплектный holy-browser:
make -B all HCC=/путь/к/hcc

# Если нужный hcc уже доступен автоматически:
make -B all
```

`make all` без `-B` — обычная инкрементальная сборка; комплектный бинарник
может оказаться новее исходников. `make clean` удаляет в том числе
`holy-browser`: сначала убедитесь, что toolchain установлен.

### Примеры запуска

```bash

# Обычный запуск графического окна X11:
./holy-browser

# Запуск в теме «Одобрение Дэвиса» (строго 16 цветов VGA, дизеринг Байера, без сглаживания):
./holy-browser --davis

# Канонический режим Терри Дэвиса: разрешение 640x480 + 16 цветов VGA:
./holy-browser --davis-640

# Запуск сразу в режиме P2P-сети Холинет с дополнительной вкладкой мониторинга:
./holy-browser --holynet --tab holy://monitor

# Снятие PNG-скриншота в headless-режиме (с вкладками и Ctrl+F поиском на странице):
./holy-browser --screenshot out.png https://www.kernel.org --modern --tab ./demo.html --find "longterm"
```

## Горячие клавиши

- `Ctrl+T` — открыть новую вкладку (`Ctrl+клик` или колёсико по ссылке — открыть ссылку в новой вкладке)
- `Ctrl+W` — закрыть текущую вкладку
- `Ctrl+Tab` — переключиться на следующую вкладку
- `Ctrl+J` — включить / выключить JavaScript на текущей вкладке с перезагрузкой
- `Ctrl+D` — добавить / удалить текущий сайт из панели закладок (`bookmarks.conf`)
- `Ctrl+F` — открыть поиск текста на текущей странице (`Enter` — следующее совпадение, `Esc` — закрыть)
- `Ctrl +` / `Ctrl -` / `Ctrl 0` (или `Ctrl + колёсико`) — увеличить / уменьшить / сбросить масштаб страницы
- `Ctrl+L` / `Ctrl+K` — фокус на умную адресную строку
- `F7` — Оракул Дэвиса (случайное слово/изречение в духе `GodSpeak` TempleOS в строке состояния)
- `F5` — обновить страницу | `F12` — сохранить скриншот окна в `screenshot.png` | `Ctrl+Q` — выход


## Тестирование

Полная проверка после установки toolchain и зависимостей:

```bash
make -B all
make test
```

Набор включает QuickJS/DOM, CSS, пакеты HOLYNET, TLS, HTTP и Tor-мост.
`tests/test_relay_privacy.py` использует Linux `/proc`, запускает комплектный
Tor и проверяет отсутствие прямых TCP/UDP-сокетов у процесса Холинета.
Сетевые возможности Tor зависят от окружения; успешный тест не доказывает
анонимность. Графические клики полностью не автоматизированы.

Отдельные проверки C-части без HolyC и запуска настоящего Tor:

```bash
make quickjs/libqjs_divine.a
cc -O2 tests/test_quickjs.c quickjs/libqjs_divine.a -lm -ldl -lpthread -o tests/test_quickjs
./tests/test_quickjs
python3 tests/test_tor_bridge.py
```

Происхождение комплектного Tor и параметры сборки описаны в
[`tor-vendor/BUILD-INFO.txt`](tor-vendor/BUILD-INFO.txt). Проверить совпадение
архива с приложенной контрольной суммой:

```bash
(cd tor-vendor && sha256sum -c tor-0.4.9.17.tar.gz.sha256sum)
```

Контрольная сумма сама по себе не подтверждает авторство. Для проверки
подписей нужны GnuPG и независимо проверенные отпечатки ключей Tor Project.

## Локальные данные

Файлы создаются в **текущем рабочем каталоге**, который должен быть доступен
для записи:

| Путь | Содержимое |
|---|---|
| `bookmarks.conf` | Закладки |
| `holynet_node_*.key` | Постоянный публичный ID профиля, **не криптографический ключ** |
| `holynet_node_*.lock` | Блокировка профиля |
| `holynet_sites/` | Опубликованные сайты и индекс |
| `holynet_peers.conf` | Файл старого механизма пиров; прямые пиры в этой сборке отключены |
| `screenshot.png` | Скриншот по F12 |

Эти данные исключены из Git. Сохраняйте резервную копию `holynet_sites/`
и ID, если хотите сохранить публикации и идентичность профиля. Не выкладывайте
локальные данные случайно. Tor использует временный каталог в `/tmp`;
аварийное завершение может оставить его на диске.

## Решение проблем

- **`hcc: not found`** — установите совместимый holyc-lang и передайте
  `HCC=/путь/к/hcc`. GCC/Clang не компилируют `.HC` вместо него.
- **`GLIBC_2.38 not found`** — комплектный бинарник не подходит системе.
  Нужна новая среда либо пересборка соответствующего компонента.
- **Нет `libX11`, `libcairo`, `libssl` или другой `.so`** — установите
  системные зависимости. Даже headless-режим использует графические библиотеки.
- **Окно не открывается** — проверьте X11/XWayland и `$DISPLAY` либо используйте
  `--screenshot` для локальной страницы.
- **Нет картинок/SVG** — проверьте загрузчики форматов GdkPixbuf и librsvg.
- **Холинет не подключается** — проверьте наличие исполняемого
  `vendor/tor/tor`, его зависимости и доступность Tor в вашей сети. Подождите
  начальную загрузку и обновите страницу; после падения Tor перезапустите браузер.
  Прямого fallback нет, `--peer` намеренно отключён.
- **Современный сайт выглядит неправильно** — HTML/CSS/JS поддерживаются
  частично; это известное ограничение, а не гарантия совместимости.
